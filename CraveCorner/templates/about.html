A note from our corner

Good food should feel like a small exhale.

CraveCorner is a fictional restaurant created for an academic project. Its purpose is to show how a real ordering workflow can use a queue data structure to treat incoming orders fairly.

The idea

Care, with a place in line.

Busy campus days already move fast. We wanted ordering to feel simple and the kitchen to feel fair. When your order comes in, it enters a first-in, first-out queue. Staff can see what’s next, move it into preparation, then mark it complete—one honest update at a time.

The menu and order status you see here come from the live service, not a demo menu tucked behind the curtain.

How the queue works

The Python backend stores active order numbers in collections.deque. Each new order is appended at the rear. Only the front order can move from PENDING to PREPARING, then from PREPARING to COMPLETED. Completion removes the front item; completed receipts remain in SQLite.

How an order moves

Menu items are loaded from Flask. Checkout sends item IDs and quantities, and the server looks up the current prices, validates the order, calculates rupees from integer paise, and saves it. SQLite restores any incomplete queue items after a restart.

Technologies used: Python 3, Flask, SQLite, HTML5, CSS3, vanilla JavaScript, Fetch API, and a Python deque. The in-memory queue is designed for a single educational app process, not a distributed production system.
